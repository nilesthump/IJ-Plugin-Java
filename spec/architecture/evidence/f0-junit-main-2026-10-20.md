```mermaid
flowchart TD
    A["提交问题、代码或 JUnit 卡片"] --> B["固定 session 输入与历史边界"]
    B --> C["首次课程检索"]
    C --> D["组装上下文并核算预算"]
    D --> E["Spring AI 调用模型"]
    E --> F{"完整模型输出"}
    F -->|"工具调用 / 结构化意图"| G[["内部 A、B：意图与工具处理"]]
    G -->|"允许继续"| D
    F -->|"回答 / 追问 / 候选"| H["显示并保存本轮结果，释放活跃槽"]
    G -->|"本轮结束"| H
    H --> I{"用户后续操作"}
    I -->|"新问题 / 补需求 / 文字决定：新一轮"| A
    I -->|"拒绝候选 / 删除卡片：更新状态"| I
    I -->|"点击同意并生成"| J[["内部 C：批准并创建测试文件"]]
    F -->|"明确文字批准"| T["保存解析结果并释放活跃槽"]
    T --> J
    J -->|"实际文件已确认"| K["回复实际文件名与跳转链接"]
    J -->|"澄清 / 失败 / 待核对"| I
```

主图保留F0的固定输入、首次课程检索、上下文预算、模型调用、工具循环及显示保存；内部故障出口在子图展开。首次检索按attempt一次，工具观察返回上下文预算，不回首检。普通回答展示后可结束；候选等待、追问等待不占活跃槽。

按钮批准直接进入内部C。文字批准先由模型提出解释，宿主核验用户原文，结束解析操作并释放槽后再开始写入操作；主图已明确显示解析与写入之间的交接节点。拒绝/删除动作必须核验明确对象，不能误删其他卡或项目文件。

主图的“显示并保存”是展示与终态收口的概括：流式预览可提前显示，只有完整、有效、耐久的候选可批准；保存失败须按F0阻塞与恢复处理，不能宣称已释放成功或已批准。内部停止/失败记录保持原资格，不混入有效历史。
