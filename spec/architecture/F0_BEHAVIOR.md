## 2. 开停入口（交互实现为提案）

建议 Tool Window 顶部提供应用级“启用/停用”和服务配置入口；此处开停是插件业务工作状态，IDE 自身的禁用/卸载仍按平台管理。首版所有项目/session 使用同一当前服务配置，不增加 session 内独立改 key；生成与嵌入服务如需不同凭据，在同一配置入口分别填入，不假设一把 key 可访问两家平台。默认提供方、准确 endpoint/modelId 与计费能力尚未由输入方式确定。

| 状态/动作 | 最小行为提案 |
| --- | --- |
| 停用 | 可填写/修改必需凭据及 profile；聊天、代码草稿、已保存 PDF 可继续浏览，不能开始模型或远程嵌入请求 |
| 启用 | 校验配置必要项并固定 configRevision/runtimeEpoch，构造客户端；未实际请求不能宣称凭据已连通验证 |
| 工作中修改 key | 服务入口与界面均拒绝，提示先停用；不能只依赖输入框置灰 |
| 请求停用 | 先阻止全部项目的新网络操作，失效旧 runtimeEpoch 并请求取消在途模型/工具/嵌入任务，按各任务边界本地收尾；旧回包不能因换 key 接回 |
| 停用完成后改 key | 保存新凭据和配置；显式再启用才使用新配置，不自动重发旧问题或继续中断工具循环 |

任务与提交固定服务配置版本，API key 不进入模型输入、聊天、普通设置或日志，优先使用平台凭据服务。停用/取消的协调方可在根对象仍可写时提交已接收累计内容的终止快照，网络回调的写入权仍已撤销；session 删除优先于此收尾。API key 单独轮换不改变嵌入空间；更换嵌入模型/维度等配置则按既有索引空间规则准备新代次，不能混用向量。

## 3. 显示档案与模型投影（选择已确认，算法提案）

聊天正文继续 Markdown/IDE 代码高亮。工具状态、工具结果和模型服务实际提供的思考信息放在独立的小字号可折叠过程区；折叠不删除内容，也不把过程正文拼成最终答案。没有思考文本时只呈现实际步骤状态，不编造思考，不为 UI 新增让模型生成解释性思维过程的请求。reasoning 字段与供应商续接协议按原始类型分开管理。

停止、超限、网络中断、停用或项目关闭时，冻结已接收的累计输出并标明未完成。已显示的思考、工具过程、正文片段继续保留在其原 attempt/branch/step；重试追加新 attempt 展示块，不覆盖旧块或清空窗口。分支切换时旧过程标为已失效但可展开回看。保存失败须提示未保存，异常退出只恢复最后完整持久化的内容，不承诺尚未落盘字节。

后续提问的模型上下文采用独立资格过滤：

1. 原用户问题、已提交代码与用户约束继续按正常历史规则使用，同一原问题不因重试重复加入。
2. 只有最终成功且正文/证据/状态已完整持久化的 attempt，其最终有效分支可提供助手历史及合法工具协议。完成显示不等于耐久成功；保存失败、状态未知、重启中断不能取得资格。
3. 停止、断流、模型输出/循环超限等未完成 attempt 的助手正文、过程/思考、工具观察和协议字段，仅供显示与档案回看，不进入后续聊天请求、检索查询、摘要输入、旧 checkpoint 或记忆缓存。可以保留“该问题未完成”的状态元数据，不能把部分输出改写成摘要事实。
4. 同 attempt 后续通识分支成功，也不使已失效分支重新取得资格。只保留实际成功有效分支所需的完整消息对；不能为满足协议从中断分支补回字段。
5. checkpoint、摘要候选与投影缓存记录投影策略版本和来源资格集合；新策略下含被排除输出的旧摘要不得复用。候选激活时校验来源仍匹配，不能只过滤尾部却继续注入受污染摘要。
6. 本次尚在进行的 ReAct 循环可以使用其配对工具结果和必需协议状态；上述排除针对后续提问。用户明确重试时从原问题/固定代码重新开始，不从旧部分回答续写。

若所选模型要求的协议历史与该投影规则不能同时满足，应停止并提示不兼容，保留档案，不擅自纳入中断内容或改变模式。普通成功历史的压缩继续按既定委托执行，原始记录不随压缩删除。

## 4. 项目迁移（用户授权代理提案）

采用 `PERSISTENCE.md` 第 5.1 节的最小路线：本机、同一插件数据存储内维护稳定 projectId，可靠移动证据可自动更新定位；复制/克隆创建新归属。原路径消失或相同名称不足以证明移动。

身份不明时提供两个明确入口：“作为新项目打开”“关联已有项目会话”。后者展示可选旧项目的名称/最后路径/更新时间，在空目标、无另一个有效实例占用且绑定版本未变时重新绑定原记录；不复制、不静默合并。目标已产生会话/草稿则不直接迁移，先保留现状并说明冲突。跨机器迁移首版暂不提供，原记录保留。本节为提案，不把具体本机范围/交互当作用户已经逐项确认。

## 6. 应用工作状态收敛（实现提案）

状态为 OFF → STARTING → ON → STOPPING → OFF。只有 OFF 可修改配置/凭据；ON 接受网络操作，STARTING 仅校验本地必要配置/构造客户端，失败回 OFF 并提示，不默认发送连通测试请求。UI 命令和核心入口共同检查状态与配置版本。

STOPPING 先封闭新工作入口并撤销旧 runtimeEpoch，再请求取消。协调方按操作身份冻结已接收内容、结束本地任务并释放活跃槽；有权限时提交终止快照，不等待远端服务器物理取消才收尾。所有旧操作已被本地失效且其收尾结果已处理后进入 OFF。

保存失败也必须有终点：保留内存渲染、明确标未保存，并将相关 session 的依赖写入/发送保持阻塞，不能把它宣告为成功保存。可以在已撤销旧操作权后进入 OFF 以修改凭据，但再次 ON 不会解除这些存储/协调阻塞；对应会话须先完成恢复/收尾验证才可新发送。旧持久任务在重开时仍按既有中断协调处理，新配置绝不接续旧任务。

应用级开停和共享资料命令由 ApplicationController 处理，session 聊天命令仍由 SessionController 处理。资料选择仅是视图状态；更换/移除提交明确 documentId 和预期版本/修订，不能把当前 session 或界面当前行当作应用命令的隐式目标。
