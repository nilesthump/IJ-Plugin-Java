## 2. 四类数据的边界（提案）

| 数据 | 内容与责任 | 压缩时的行为 |
| --- | --- | --- |
| SessionDraft | 当前 session 待发送的文字、代码片段及固定快照引用，带 draftId/revision | 未提交内容不进入历史摘要、检索查询或 LLM 请求 |
| SessionArchive | 已提交的有序原始消息、typed parts、固定代码快照、请求结果和回答来源记录 | 压缩不删除、覆盖或重新解释原始记录；用户主动删除 session 则清除其全部记录 |
| CompactionCheckpoint | 覆盖某个完整历史前缀的有损摘要、来源范围及版本信息 | 作为可校验、可失效的派生背景，不作为新的用户指令或课程证据 |
| LlmInputProjection | 本轮固定提示、有效摘要、近期原文、当前提交及课程证据的文本化结果 | 由请求快照派生，按实际模型输入预算校验 |

草稿中的代码快照属于该 session；草稿文字、代码片段及标签布局跨重启恢复已获确认，正常保存/恢复提案见 `PERSISTENCE.md`。手动压缩只处理已提交历史，不能把尚未提交的选区一起发出。

完整历史的保留与模型本轮可见内容分别管理。历史被摘要覆盖不等于聊天窗口隐藏原文；从持久记录回看旧消息，仍按原 schema 渲染代码片段。

## 3. 待发送区到请求的提交（提案）

1. 右键动作定位编辑器所属项目的当前 session；缺省新建，追加新的 CodeSelectionPart/CodeSnapshot 到该 session 的草稿。
2. 用户提交问题时，读取明确的 sessionId、draftId/revision 和有序 parts，形成一次提交身份及 user message。
3. 新提交在同一短事务中检查 session/单任务槽、精确草稿 revision 和捕获组就绪，写入原始消息/快照引用及操作身份，再消费该草稿版本。新编辑先提交则旧发送版本过期、不消费草稿；发送先提交则后续编辑进入后继草稿，不被旧提交清空。事务失败不调用模型。
4. 作用域/当前实例/session 可用性校验后，先按提交身份识别重复交付，再对新提交执行上一步检查；重复只返回原提交身份，不追加消息或再次调度。实际使用重试关联原提交与新的请求尝试，不重复追加问题，具体参数由执行成员确认。
5. 固定本轮 message/part 截止点；后续的编辑器变化、标签切换或草稿修改不改变这个请求。

已提交的当前问题和代码作为本轮输入材料保留；后续压缩或网络异常在开发时暴露、实际使用时提示并按明确规则降级，不能回滚为未提交或覆盖已保存材料。

## 4. 输入预算（数值由执行成员实施确认）

建议每个生成模型配置记录：实际上下文窗口 W、请求输出预留 R、供应方其他必要预留 P、安全余量 M，以及独立输入上限 L（若服务有该约束）。

本轮输入预算 B = min(W - R - P - M, L)；没有独立 L 时只使用前一项。R 受实际请求和服务输出上限约束，不直接照搬历史总结中的最大输出预留。

输入计量覆盖：固定提示和序列化开销、摘要、近期原文、当前问题、代码正文、课程检索片段及其他确实发送的文本。检索模型和摘要调用有各自的输入/输出限制，不能只验证主聊天请求。

方法全文及类结构同样占用输入。重叠整理仅在同版本/范围可验证时处理自动补充内容，保留原选区身份及关注位置，不跨用户捕获动作按文本去重；原始快照不因投影整理改变。补充内容过大时提示容量，不静默裁剪方法或以摘要替换本轮必要代码。

优先使用实际模型可用的计量方式；本地估算须标注其估算性质，并结合已提交请求的 usage 校准。草稿阶段的容量预览采用本地估算；向外部服务发送内容的计量调用也受提交边界约束。

自动触发点必须低于硬输入上限，并给摘要调用留出空间。具体 Token 数、比例和保留轮数由该任务执行成员根据实际模型/课程平台契约及样例效果选定并验证，不采用 TXT 中的固定阈值。

## 5. 分层整理（提案）

先重新构造本轮必要输入：同一 partId 只投影一次；旧请求的 RAG 大段正文不作为永久附加内容反复注入；当前课程证据按照相关性和本轮预算选择，并同步维护实际提供给模型的引用集合。

这种整理针对派生输入中的重复和可重新取得材料，不删除用户追加的历史代码片段。文本相同但 partId 不同的两次选区仍保留其原始身份。

仍接近预算时，对较早的已终止轮次生成摘要，保留近期完整轮次和当前提交。“完整”表示不切断终止轮次的记录，不要求回答成功；失败/取消/中断的轮次仅保留用户问题/代码与未完成状态；其中助手部分正文、思考/工具观察和协议输出不得进入摘要输入，在途与当前提交不覆盖。用户已采纳 ReAct，工具请求/结果及必需协议字段须配对保留；本次活动循环不压缩。较早已终止轮次的压缩需验证供应商协议兼容，不为复刻 Microcompact 新增通用框架。

当前问题、当前提交的代码等必要材料本身过大时，应报告容量问题并保留档案/草稿恢复入口，而不是无提示截断源码。若相关课程证据因预算无法提供，要区分容量不足与检索正常无命中。

## 6. 检查点的最小模型（字段为提案）

| 对象 | 建议字段 |
| --- | --- |
| SessionContextState | sessionId、activeCheckpointId、当前 compactionJob、策略版本 |
| CompactionCheckpoint | checkpointId、sessionId、parentCheckpointId、覆盖起止序号/轮次、源前缀 hash、摘要正文、code/evidence refs、生成模型配置、schema/投影版本、状态 |
| CompactionJob | jobId、sessionId、请求打开实例、基准 checkpoint、固定目标边界、预算、状态与调用身份 |
| ContextBudget | 生成模型配置、上下文/输入/输出约束、估算方式、当前各类输入占用及预留 |

摘要建议包含：当前用户目标、用户明确的约束与后续纠正、已讨论结论及尚不确定事项、未解决问题、下一步、需要精确恢复的代码快照引用，以及历史课程证据引用。

用户原话、助手建议、未证实推断与课程事实在摘要中保留来源区别。摘要只提供背景；将摘要放进模型输入不提高其中内容的指令优先级，也不能把助手旧回答升级成课程材料。

程序可检查覆盖范围、对象归属、hash、引用存在性和预算，但这些检查不能证明摘要语义无遗漏。摘要质量需用实际会话回放和约束保留样例验证。

## 7. 压缩与激活流程（提案）

用户已确认每 session 同时只执行一个生成/整理任务。自动压缩属于本次回答内部阶段，手动压缩独立占用同一活跃操作位置；忙时不接收新的发送/整理任务、不排队，新内容仍可编辑并保存在草稿。关闭标签任务继续，可从会话列表重开。任务结束不自动提交草稿。

入口分两种：手动压缩只读取已提交历史，生成/激活检查点后更新状态并结束；不会据此检索课程材料或生成新回答。下列步骤描述用户提交问题后触发的自动路径。手动路径复用前缀选择、摘要及激活规则，但没有“继续生成回答”步骤。

1. **规划**：固定本轮请求、历史边界和有效 checkpoint；检索本轮课程证据，构造并计量完整输入。
2. **选定前缀**：只覆盖较早的已终止轮次，先按最终耐久成功及有效分支过滤生成内容；未完成轮次只保留原用户输入和状态，排除部分正文/思考/工具/协议输出；保留近期符合资格的完整轮次及当前提交。范围、摘要与尾部不能重叠注入或留下未说明的缺口。
3. **生成候选**：以预算内的历史前缀和必要旧摘要生成候选摘要。使用隔离的摘要调用，不执行工具，不把压缩提示/答案写成普通聊天消息，也不经同一个记忆 advisor 追加回主会话。
4. **校验**：检查 session 仍存在、目标前缀内容/边界一致、基准 checkpoint 未被并发替换，检查本 session 的代码/来源引用及候选大小；重建并重新计量完整主请求。
5. **激活**：候选与元数据先完整保存。原子切换 activeCheckpointId 的同一提交条件中，再确认 session 存在、任务未取消、基准 checkpoint 未改变、目标前缀仍一致；不只依赖前一步的较早校验。正常尾部追加不阻止有效前缀激活。等待 LLM 时不持有存储事务；未完成不覆盖之前 checkpoint 和原档案。异常传播到明确边界，按开发/实际使用策略分别处理。
6. **继续**：使用本轮冻结的投影调用生成模型，结果按原 session/turn/request 归属返回。

按已确认单任务规则，压缩期间不接受本 session 的新发送，但允许编辑草稿，草稿变化不改变已提交前缀。覆盖规则仍以固定前缀为准；将来的尾部追加不能误计为已压缩，正常尾部追加不天然使已有前缀摘要无效。后续重试建议追加关联原问题的新尝试记录，不改写被摘要的旧尝试；从原 message/part 固定快照恢复本次必要问题和代码，不以摘要代替当前输入，新结果追加到未覆盖尾部。

源码回查使用该 session 保存的固定 CodeSnapshot，不从后续修改的编辑器文件“重建”旧代码。需要恢复的代码 partId 与近期历史去重后只加入一次，再核算预算。

旧摘要和旧引用不是本轮课程检索证据。回答需要引用课程材料时，取实际可核验的来源记录/片段正文，并保持文档版本和物理页码；摘要不能生成替代页码。

## 8. 下一轮输入的组成（提案）

固定提示及协议说明 + 按当前投影资格生成的有效历史摘要 + 覆盖边界后通过资格筛选的历史（含原用户输入和本轮提交）+ 按需恢复的旧代码快照 + 本轮实际课程证据。

普通文字/代码片段最终转为所选聊天接口支持的文本，保留原始消息角色/顺序及来源标识；结构化工具调用、工具结果与必须回传的供应商字段按接口原生协议保留，不扁平化为普通聊天文本。压缩边界和恢复状态是本地元数据，不要求 DeepSeek 或课程网关识别 Claude 的 compaction block。

应用 ContextPlanner 负责这份投影时，不能再让框架记忆 advisor 自动追加另一份相同历史。Spring AI 的有限消息窗口可作为适配/缓存选择讨论，不能替代完整档案或语义压缩控制。

## 9. 开发暴露与实际使用降级（提案）

| 情况 | 建议行为 |
| --- | --- |
| 摘要为空、格式/引用无效、调用超时等异常 | 不激活候选；开发暴露原错误。实际使用提示整理失败，按下述预算规则继续或暂停发送 |
| 显式取消或提交条件不再成立 | 正常停止本次任务，不激活候选；通过明确状态处理，不捕获任意异常冒充取消 |
| 摘要后仍超预算 | 不无限递归压缩；如果必要输入仍放不下，阻止本次模型发送并明确容量状态 |
| 摘要调用自身放不下历史前缀 | 规划阶段报告容量限制并停止；MVP 不追加分组摘要或递归压缩兜底 |
| 正常历史尾部追加 | 新消息留作未覆盖原文，按请求快照和下一轮规划使用 |
| session 删除或项目旧实例迟到回包 | 不更新有效状态，不重新创建已删除 session |
| 激活过程中崩溃 | 恢复最后完整提交的 checkpoint；未提交候选不成为活动上下文 |
| 重启读取发现版本/来源不匹配或损坏 | 开发暴露校验错误；实际使用提示恢复不完整，保留原数据，只能使用验证完整的档案/检查点，不把损坏候选当有效状态 |

具体超时、尝试上限及必要失败控制参数继续交由该任务执行成员确认，不复制 TXT 中的失败 3 次，也不叠加隐藏重试。开发/调试时异常暴露并中止，不默认走降级使验证通过。实际使用时先提示压缩失败，可使用旧有效 checkpoint 加未覆盖原文、本轮提交和本轮证据，重建并重新计量投影；满足预算才继续，否则暂停本次发送并保留材料。不能直接复用上一轮投影、遗漏当前问题/代码或无提示截断。持久化状态不确定时，先停止依赖该提交的发送，不将“仅在内存”宣称已保存。

摘要调用也消耗额度和时间，记录独立 purpose/usage；不能只把最终回答的 usage 当作总消耗。具体服务是否提供可用计量字段仍待接口验证。

## 10. 界面与持久化边界

自动压缩接近模型输入预算时触发，手动入口已由用户确认。手动入口针对当前 session 的已提交历史；草稿保留在待发送区。

建议标签页呈现“整理上下文中/完成/失败”状态，并允许查看完整原消息。压缩事件独立于用户/助手聊天记录，避免把内部摘要当成新回答。按钮位置、占用指标和失败后的具体交互仍是界面提案。

保存聊天、附加代码快照、全部草稿及标签布局是已确认要求；checkpoint 的保存用于重用已完成摘要，是实现提案。具体存储与保存时点仍待选择；MVP 不自动清理/修复摘要候选。

普通关闭标签不停止手动或自动整理；重新打开绑定原 session，不重复发起整理。通过标签删除 session 后，历史、代码、草稿、checkpoint/候选、任务/用量/错误记录及记忆缓存都随之清除；取消在途任务，迟到摘要不得再激活。删除范围与提交保护见 `PERSISTENCE.md` 第 6 节。

## 11. 验证场景（尚未执行）

1. A/B 两个 session 有不同代码和约束；压缩 A 的输入、输出和激活都不使用 B 的数据。
2. 待发送区有代码 S 和文字；手动整理或历史自动压缩不把它们提交、检索或发送。提交后 S 只作为同一 partId 出现一次。
