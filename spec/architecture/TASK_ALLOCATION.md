## 并行边界与依赖

负责人先给出最小接口与样例，而不是先实现全部核心。以下名称是概念契约，正式字段仍以后续确认的消息/分页/视图模型为准。

- 成员甲依赖 SelectionCapture → SelectionSink、代码快照及统一 session 入口（早期概念名 AskIntent 由此细化）。适配器捕获源项目和选区/方法/类结构，不实现第二套全局活动会话或直接请求 LLM。
- 成员乙依赖 PDF 固定快照输入与 PdfReadResult；负责人负责业务文档身份和索引目录。分页适配器不拥有分块策略或向量库选择。
- 成员丙依赖 SessionViewState、消息片段类型和 ViewEvents；可先用模拟消息完成 Markdown 与 IDEA 多色代码渲染。负责人协调库/平台依赖、公共 DTO 和兼容验证；新增渲染成本需实测，不改变 5:1:1:1。持久化、请求生命周期及删除语义通过负责人服务实现。

三个适配器均可在模型平台接口尚未完成时并行推进。公共契约变更由负责人协调；每位成员提交所属模块的必要验证证据、接入说明和报告素材，负责人汇总整体架构、报告与演示材料。

并行启动的具体契约、模拟输入和修改归属见 `PARALLEL_START.md`、`parallel-examples.json`。先完成最小公共准备，再四人并行、分阶段替换模拟组件；当前只是设计包，尚未实现插件骨架或可调用 mock。公共工程配置/插件注册/契约由负责人协调，各适配器只改自己的模块及样例，不由四个 AI coding 会话同时覆盖公共文件。
