## 2. 逻辑存储职责（提案）

| 职责 | 归属与内容 | 保留/重建原则 |
| --- | --- | --- |
| CourseSourceStore | 应用级共享的托管 PDF 字节、文档身份、导入版本、内容 hash、显示名 | 耐久原始资料；外部原路径只作来源信息，不承担唯一定位 |
| CourseIndexStore | 分页文字、片段、嵌入配置、索引代次和激活指针 | 派生数据；可按固定源版本和处理配置重建，更新失败保留旧就绪代次 |
| SessionStore | 项目关联、session 元信息、原始消息、有序 typed parts、选区/方法全文/类结构快照、草稿、请求状态、回答及证据记录 | 耐久业务记录；查询和写入校验 session 归属，不汇入共享课程库 |
| ToolProtocolStore | session 所属 attempt/branch/step、工具请求/结果、状态及模型续接字段 | 私有耐久记录；不混入 Markdown 正文，不随项目复制，session 删除时清除 |
| ContextStateStore | session 内 checkpoint、覆盖范围、引用和活动指针 | 派生背景；不能替换原文。实际使用故障可退到验证完整的档案/旧检查点，先提示并重新检查预算 |
| ProjectViewState | 稳定项目关联、打开的 sessionId、有序标签和 activeSessionId | 恢复视图；标题、顺序与窗口焦点不承担持久身份 |
| ProviderSettings / Credentials | 非秘密的服务配置/profile 标识、工作状态/配置版本；凭据单独保存 | API key 使用平台凭据服务；不写入聊天、草稿、PDF 元数据或普通设置正文 |

这些是逻辑责任，不意味着每项各建一个数据库或进程。共享课程库由应用级服务管理，项目级服务协调本项目会话；session 的身份和数据隔离独立于服务实例生命周期。关闭项目或释放服务不删除耐久记录。

非秘密设置可使用平台状态持久化机制；不断增长的聊天、代码、PDF 和 checkpoint 交给业务存储。为让 session 删除与标签引用更新共同提交，当前优先提案将 ProjectViewState 也放入同一业务存储，界面不再另存可复活旧标签的权威副本。不能把“内存中的设置已更新”当作“用户消息已提交到磁盘”。恢复需要的唯一副本不只放在可清理缓存目录。平台保存语义核查见 `evidence/persistence-research.md`，工程提交提案见 `ENGINEERING_BLUEPRINT.md`。

## 3. PDF 导入版本与旧回答（提案）

1. 将所选文件复制到托管暂存区；复制完成后对该副本计算 MD5 并校验可读性，按用户指定规则查重。解析、预览和索引均消费同一固定副本，不在后续阶段重新读取外部可变文件。
2. 以独立的 documentId / sourceVersionId 记录逻辑资料及实际字节版本。相同文件名不意味着同一版本；内容 hash 不替代业务身份。
3. 源副本及版本记录完整保存后，按既定入库流程准备新索引。只有通过校验的索引代次成为可检索状态；失败的导入/索引任务有明确状态，不能表现成“正常无命中”。
4. 回答记录保存实际证据的 sourceVersionId、chunkId、显示名、物理页码/范围及使用的索引代次。引用点击按对应托管版本打开，而不跳到“最新版相同页码”。
5. 更换嵌入模型可重建索引，不能改写旧回答来源。正常清理可重建索引时，仍保留旧回答所需的来源定位与证据记录；被保留回答引用的 PDF 版本不随索引清理自动删除。

PDF 物理页从 1 开始与印刷页码分开建模，具体显示规则仍待细化。用户已选择资料视图选中资料后更换/移除及 MD5 排重（user-turn-033 更正），剩余移除/容量清理由代理提案，见 COURSE_LIBRARY.md；用户主动删除 session 的全部记录要求见第 6 节，不沿其证据引用删除共享课程资料。

## 4. 写入与提交的一致性（提案）

| 写入边界 | 必须共同成立的状态 |
| --- | --- |
| 草稿修改 | sessionId、draftId/revision、有序文字/代码片段和所需固定快照可共同恢复；保存完成状态只在确实写入后更新 |
| 用户提交 | commandId 去重、原始用户消息及快照引用入档、该次提交消费的草稿内容更新为一个逻辑提交；任何一步失败都不能丢失草稿或留下缺正文消息 |
| 回答完成 | 回答正文、对应 requestId、实际来源记录与完成状态一起可恢复；不能先显示“已保存完成”再遗漏来源 |
| checkpoint 激活 | 候选完整保存后，在同一原子条件更新中检查 session/取消状态、基准 checkpoint 和被覆盖前缀；规则沿用 SESSION_CONTEXT.md |
| 索引激活 | 新代次完整可读、身份/配置校验通过后切换活动指针；在途请求固定原证据版本，不被切换改写 |

同一 session 的本地状态写入有明确顺序。提交冻结确切草稿版本；期间新增或修改的内容不能被旧提交整段清空。存储适配器应提供短时的原子提交/条件更新能力；等待远程嵌入、摘要或回答时不持有存储事务。

第一版流式显示已确认。建议保存 attempt 的累计 partialBody + throughSeq + incomplete，按短批次提交，不做逐 token 日志；旧前缀不能覆盖新前缀/终止结果。最终完成标记需与正文、实际证据和终止状态共同成立。实际使用断流保留部分正文并标记未完成，不自动重发整请求；用户重试建立新 attempt 关联原问题，新回答不拼旧前缀。关闭标签后任务继续，重开读取核心累计状态，不重新订阅。具体契约见 `STREAMING_RESPONSE.md`。

这些一致性约束由短事务/条件写入保证。核心读写异常传播到任务边界；开发暴露原错误，实际使用明确提示未保存/读取失败，并暂停受影响写入或发送，维持可验证的浏览能力。不能捕获写入错误后假定已保存并继续提交；已提交数据不因后续错误被主动覆盖，资源照常释放。

## 5. 重启恢复顺序（提案）

1. 读取存储版本和稳定项目关联，验证原始会话档案；新建本次 projectInstanceId，不恢复旧运行实例身份。首次尚无记录采用明确的初始状态；损坏/不支持版本在开发时暴露，实际使用提示并限制受影响功能，不清空后伪装首次启动。
2. 恢复消息顺序、typed parts、固定代码快照和每个 session 的草稿；校验引用属于该 session。源代码文件后续变化不替换保存的代码正文。
3. 校验活动 checkpoint 及其来源；没有已激活 checkpoint 是正常状态。开发暴露读取/校验错误；实际使用提示后，可从完整有效档案重新规划或使用有效旧检查点，不能使用损坏记录或覆盖原档案。
4. 按已保存的 openSessionIds、标签顺序及 activeSessionId 恢复本项目视图。正常删除 session 时同步更新布局，不凭布局复活对象；布局损坏在开发时暴露，实际使用提示恢复不完整并提供从有效会话列表重新打开的路径，不静默伪装布局完全恢复。
5. 运行中的请求和压缩任务不恢复成正在执行；建议标记为中断并保留已保存材料，等待用户明确重试。恢复草稿与标签本身不触发检索、摘要或生成请求。
6. 读取课程库激活代次。正常未导入/未激活与读取异常分开；实际使用索引故障要提示 RAG 不可用，并提供重建入口及明确标记的通识路径。历史回答的来源定位绑定托管 PDF，不依赖重新调用模型或当前索引。

正常退出应完成待写草稿与布局的保存；异常退出恢复到最后完整持久化版本，不承诺尚未写入的每次按键也能恢复。具体保存频率、刷新机制与关闭时等待策略由实现验证，不能只依赖 IDE 偶尔保存设置。

同一 IDE 内关闭再打开项目也要协调旧实例操作，不只在 IDE 重启时处理。关闭时先失效旧回包权，由生命周期协调方委托应用级存储按原实例/operationId 条件记录本地终止并释放其活跃槽；重开先完成旧实例协调，再允许新操作。该权限不依赖已失效的回调，不能清掉新操作，也不写回删除中的 session。详见 `ENGINEERING_BLUEPRINT.md` 第 6 节。

### 5.1 项目移动与复制（行为已确认，身份算法为提案）

会话归属采用稳定 projectId，当前项目路径只是可更新的定位信息；projectInstanceId 仍只表示本次打开。最小提案由应用级 H2 保存项目身份、定位、已观察的目录身份和会话数据，无需向项目写入会被复制的 UUID，也不把会话数据库随源码目录复制。这里“跟项目移动”指会话归属和恢复结果随移动保留，不要求搬动应用级数据库或共享课程库。首版提案覆盖同一机器/同一插件存储内的项目移动，跨机器迁移尚未定义。

| 场景 | 处理规则 |
| --- | --- |
| 原路径正常重开 | 校验定位及目录身份连续性后恢复原 session、聊天/快照、草稿、checkpoint 和标签布局；同路径被重新克隆/替换不能只按路径接回 |
| 已证明的移动/改名 | 保留 projectId 和 sessionId，条件更新项目定位，恢复全部原会话；原始代码快照及历史来源标签不改写，之后捕获使用新路径 |
| 项目副本/克隆 | 分配新 projectId，初始会话列表与布局为空；源码或 IDE 项目设置相同不授予原会话访问权；原项目记录保留，共享课程库仍可使用 |
| 定位或目录身份变化，移动/复制无法判明 | 暂不接回旧会话，明确提示身份待确认；提供“作为新项目打开”或“迁移已有项目会话”入口，不自动转移、复制或删除旧记录 |

UUID 标记本身可被复制，单靠标记无法区分移动和复制；只按路径关联又会丢失移动后的归属。自动重绑定需有可靠的正向移动证据，例如本插件跟踪的移动操作或经验证的目录身份连续性。原路径消失、文件内容相同和项目名称相同都不足以独立证明移动；离线跨卷移动与复制后删除原目录可能不可区分。具体平台事件/目录身份能力仍需验证，不承诺任意离线操作都能无提示识别。

绑定校验在恢复会话及接受任何 session 读写之前完成，不能先显示历史再检测复制。显式迁移是重新绑定原记录，不复制记录；仅空目标可直接重绑定，目标已有会话/草稿时不静默合并、覆盖或改归属。事务校验旧绑定未改变且不存在另一个有效项目实例占用，协调旧实例任务后更新定位/绑定版本，再建立新 projectInstanceId。不能仅检查原目录是否存在；文件系统大小写/路径别名应先归一到同一定位，真正的副本使用独立归属。绑定保存失败须提示并限制相关持久化，不静默共用旧项目。移动识别与重新绑定不授予旧回调新的写入权。

## 6. 删除 session 的清理边界（范围已确认，算法为提案）

标签提供独立的删除会话动作。普通关闭标签保留记录并允许后台任务继续；删除则移除对应全部记录，不保留可恢复的软删除档案。清理范围至少包括：

| 所属记录 | 删除内容 |
| --- | --- |
| 会话档案 | session 元信息/项目关联、所有消息及片段、回答正文和部分回答、代码快照、轮次与请求尝试 |
| 待发送内容 | 全部文字、代码片段、草稿版本、未提交快照及延迟保存内容 |
| 上下文状态 | 活动和历史 checkpoint、摘要候选、压缩任务记录、本 session 的模型记忆、工具轨迹/协议状态和输入投影缓存 |
| 私有证据与诊断 | 回答证据副本/引用、本 session 的错误/用量记录、临时数据及本插件管理的会话恢复副本 |
| 视图与检索入口 | 会话列表条目、打开标签/顺序/activeSessionId 引用、按该 session 保存的通知和恢复缓存 |

共享课程 PDF、文档版本、索引和其他 session 记录保留。共享资料的旧版本清理是独立策略，不能因删除一个回答的引用而级联清除课程来源。

建议顺序为：

1. 按稳定 sessionId 撤销任务、捕获、延迟写入及尚未落盘的新建预留票据，停止新业务变更；通过同一 session 命令顺序，短事务提交 DELETING 栅栏并移除普通视图入口，再向底层任务发出取消。若根记录尚未创建，撤销创建票据，迟到初始化不得 INSERT。
2. 在栅栏后清除相关私有文件、恢复副本、模型记忆和内存缓存。最后一个短事务清理全部私有子记录、根记录及残余布局引用；保留完成跨介质清理所需的身份直到对应步骤完成，不把标签消失等同于清理完成。
3. 所有 session 所属业务状态写入通过同一提交规则，在短事务内锁定/条件更新根状态并校验操作有效性；普通写入要求可用，清理命令允许在 DELETING 下执行，共享课程写入走应用级规则。不能先查再在事务外写入，布局、捕获、草稿与诊断同样适用。禁止自动新增复活，sessionId 不复用。
4. 清理完整后才反馈成功；实际使用清理异常要提示“删除未完成”并保留继续清理入口，开发暴露原错误。未完成栅栏在重启后不恢复为可聊天档案，成功后不留软档案或清理记录。

本段仅针对正在删除的 session：运行任务在取消尚未结束时仅可保有阻止迟到写入所需的临时运行状态，不能再保存该 session 的内容或诊断；普通停止/中断的协调方收尾另按 F0_BEHAVIOR.md 保存已接收终止快照。删除不自动新建替代会话；后续右键选区按当前打开标签规则定位，缺省新建。关闭/删除动作都会更新布局，重启不得按旧布局恢复已删除 session。

DELETING 栅栏使更晚业务写入被拒绝，更早已完成写入一并清除。具体首次创建竞争、提交顺序与运行验证见 `ENGINEERING_BLUEPRINT.md` 第 3、5 节，仍是提案。

## 7. MVP 范围与存储选择（提案）

业务记录包含 schemaVersion，消息片段、投影和摘要策略版本分开。MVP 不实现通用迁移或万能数据修复框架；开发遇到错误直接暴露，实际使用提示并停止受影响写入，保留可验证的功能。不能清空数据后伪装首次启动，必要降级边界见 `ERROR_HANDLING.md`。

业务数据库采用 H2，具体版本、表结构、向量编码和目录尚未选定。需验证：打包体积及目标 JBR 兼容、提交/条件更新能力、有序读取与 session 隔离、按 session 清除所有记录/缓存的能力、PDF 大文件旁存、异常退出后能读取最后完整提交。优先减少自制存储机制；不能仅靠逐个覆盖文件冒充事务。嵌入式 JDBC 装配、连接及生命周期仍需实测。

用户已指定 JVector，替代自定义全库精确扫描，并采用 H2。基于首版规模与单 IDEA 进程范围，H2 保存业务记录/原始向量，PDF 旁存，JVector 内存图从固定耐久代次后台构建/恢复为优先实现提案；图、原始向量及 ordinal→chunk 映射同寿命。具体恢复/激活/查询资源与 ANN 验证见 `JVECTOR_RETRIEVAL.md`。两个产品的版本均未锁定；HTTP/查询取消与数据库短事务分开，不中断数据库 I/O，不开启额外服务绕过多进程占用。

项目移动保留会话、复制不继承已确认；第 5.1 节身份算法及其平台验证仍待落实。容量限制和共享旧源版本清理已有 COURSE_LIBRARY.md 的 MVP 提案；session 主动删除全部所属记录已确认，聊天压缩本身不触发删除。摘要模型、Token 预算、压缩失败参数继续由对应任务执行成员确认。

## 9. ReAct 持久化补充（提案）
