入库与问答分成两条独立讨论线：前者负责用户在插件内选择课程 PDF 并建立索引，后者消费已就绪的索引。远程嵌入会引入入库及查询阶段的网络依赖。

生成服务提供 DeepSeek 和课程平台配置来源；当前 MVP 提案为应用级当前 profile，停用后修改并显式再启用，不提供自动主备切换或 session 内独立改 key。准确模型/接口仍需核验，这不额外制造必须先问用户的开工问题。平台配置、模型选择和请求能力属于适配器契约；不在 UI 中要求用户理解内部组件结构。

## 10. 本轮细化：PDF 入库与引用链（提案）

建议的责任顺序：用户在插件中选择课程 PDF → 取得固定快照并记录文档身份/内容版本 → 按物理页提取 → 页内清理/分块并保留来源 → 远程嵌入 → 写暂存索引 → 校验 → 激活代次。

“远程嵌入”是符合用户体积偏好的优先评估路线，仍依赖实际服务支持；用户并未禁止本地嵌入。插件内选择 PDF 已获用户确认；导入进度、失败信息与就绪状态的具体界面待细化。

页内分块有利于准确引用，也可能切断跨页句子或代码；先用真实资料检查检索质量，再决定是否引入跨页片段及来源跨度映射。PDF 第 N 页使用从 1 开始的文件物理页，不直接等同于印刷页码。

| 记录 | 用于讨论的最小字段 |
| --- | --- |
| CourseDocument / SourceVersion | 业务 documentId、显示名、源文件指纹、物理页数、固定源版本的定位方式 |
| PageRecord | documentId、源版本、physicalPage、提取状态；pageLabel 和印刷页码映射为可选字段 |
| KnowledgeChunk | 业务 chunkId、documentId、源版本、处理配置版本、页内序号、文本、pageStart/pageEnd |
| IndexGeneration | generationId、状态、预期/已写入块数、失败摘要、embeddingSpaceId、向量维度 |
| AnswerEvidence | 本轮实际检索的 chunkId、来源版本、显示名、页码以及临时引用标识 |

文件名只承担显示和定位；文档身份与版本不依赖同名文件。分块器输出中的父 ID 不能替代业务文档版本。无文字页单独记录，不因提取列表少了一项而给后续页重新编号。

模型获得的是本轮证据集合及引用标识；应用将标识回查到检索记录后显示“资料名，PDF 第 N 页”。未知标识不能包装成已验证来源；正确格式和存在的来源也不能自动证明回答语义受该材料支持。

建议采用“暂存 → 校验 → 激活”：重复文件版本和处理配置应能识别；新版本未完成不切换旧激活代次。开发暴露异常，实际使用提示导入失败并可继续使用明确标识的旧就绪版本。用户已确认保存托管 PDF，引用对应导入版本；旧回答据此定位的存储方案见 `PERSISTENCE.md`。MVP 提案以单资料任务为发布单位；如提供批量入口，各资料独立准备/发布，不增加跨资料全有全无事务。其余细则见 COURSE_LIBRARY.md，不再将其当作必须重新询问的需求。

## 11. 本轮细化：远程模型与失败边界（提案）

建议把生成配置和嵌入配置分开：生成服务记录提供方、base URL、model ID 与凭据引用；嵌入服务另记相应信息、维度及模型版本/身份。具体 endpoint、账户能力、配额均需核实，不在讨论记录中填写密钥。

文档与问题必须使用兼容的嵌入空间。embeddingSpaceId 应绑定实际嵌入提供方/模型、向量维度与影响表示的处理配置；配置变更后需检查兼容性，不能仅凭维度相同混用。更换生成模型与更换嵌入模型的影响分开：前者通常无需重建向量，后者通常需要新索引代次。

| 情况 | 建议的可观察行为 |
| --- | --- |
| 正常检索无相关材料 | 自动继续通识回答，明确标注“无相关资料”，不伪造课程引用 |
| 无激活索引 | 自动继续通识回答，未建库时标注“未建课程库”；导入中/尚无就绪索引按真实状态说明，不伪装成正常无命中 |
| 入库嵌入异常 | 开发暴露原错误；实际使用提示失败，新代次不激活，已有就绪版本可继续使用并明确其版本 |
| 查询嵌入或检索异常 | 开发暴露原错误；实际使用提示课程检索不可用后自动继续通识回答，明确标注未使用课程证据，不伪造课程引用 |
| 生成服务异常 | 开发暴露原错误；实际使用提示回答失败/未完成，保留输入和历史并提供重试；不自动切换服务 |
| 引用标识未知或来源版本不可定位 | 标记引用问题，不能悄悄改指向新版文件同页码 |

以上流程、数据结构与失败策略仍为代理提案。资料供应方式已确认，下一步核实实际嵌入服务、H2/JVector 的结构/运行兼容；详细验收按用户答复继续待定。

用户报告的平台候选 bge-m3 与 qwen3-embedding 分别作为可配置嵌入来源讨论，不同时混入一个向量空间。qwen3-embedding 是家族/平台别名线索，具体尺寸、输出维度与接口所用前缀或指令策略仍需平台说明确认。暂不选默认赢家，也不假定文档与查询接口会自动采用一致策略。

BGE-M3 原模型 dense 输出为 1024 维；Qwen3-Embedding 家族存在不同尺寸及可调维数，故平台实际输出仍需核实。文档与查询遵循模型配套的编码约定，输入不一定使用相同前缀；平台是否自动添加指令也是接口契约的一部分。原模型资料与平台实际 API 能力分开记录，见 `evidence/model-api-research.md`。

## 13. Session 与对话窗口

### 13.1 已确认的产品行为

课程库共享。对话历史和代码上下文以 session 为隔离单位，同一项目可以创建多个 session。每个 session 渲染为一个对话窗口，重启后恢复该 session 的聊天记录和附加代码快照。

这里的对话窗口指 session 的聊天视图，容器已确定为 Tool Window 内标签页切换。每个标签绑定对应 session，同项目的多个 session 分别呈现。共享课程库不包含自动汇入其他 session 的问题、聊天历史或代码快照。

### 13.2 责任与身份映射（提案）

| 层级 | 建议责任 | 数据归属 |
| --- | --- | --- |
| 共享课程库 | 文档版本、片段、嵌入空间和激活索引代次 | 供各项目及 session 检索的课程资料 |
| 项目会话协调器 | 列出、创建和恢复本项目的多个 session，管理当前项目打开实例 | 项目与 session 的关联、窗口焦点 |
| Session | 聊天档案、代码快照、上下文选择、运行请求 | 独立 sessionId，不能以 projectId 代替 |
| 对话窗口 | 渲染绑定 session 的消息、附件、输入与请求状态 | 由 session 状态派生；窗口标识不承担会话持久身份 |
| 请求 | 固定本次历史边界、问题、代码上下文与证据 | sessionId、turnId、requestId、projectInstanceId |

优先讨论由 application-level Service 管理共享课程库、project-level Service 管理本项目的多个 session。用户已确认首版共享范围为同一个 IDEA 进程内的多个项目/session，不要求多个独立进程同时读写；H2 产品已定，连接管理、版本和生命周期实现仍为提案。

sessionId 应稳定且唯一；标题、标签位置、项目名称和当前焦点都不能代替身份。项目与持久化会话之间需要可恢复的映射。用户后续确认会话跟项目移动、复制不继承，身份提案见第 25 节及 `PERSISTENCE.md` 第 5.1 节；不从这条决定外推任意跨项目复用。每次打开项目的 projectInstanceId 与持久项目身份分开，避免旧运行实例回包写入重新打开后的界面。

Spring AI 的 conversation ID 按 sessionId 赋值；完整历史与模型输入窗口分开管理。代码快照和应用状态仍由 session 自己管理，设置 ChatMemory 的 conversation ID 不会自动隔离所有应用对象。依据见 `evidence/session-scope-research.md`。

### 13.3 发起请求与响应路由（提案）

右键选区提问的目标已确认：进入编辑器所属项目的当前 session 标签，没有可用的当前会话时新建。发送时固定目标 session，再冻结该轮的历史边界、问题和代码快照。后台任务消费不可变文本，不反复读取后续编辑器选区；后续标签切换不改变已建立的归属。

当前会话状态建议按项目维护 activeSessionId，避免使用跨项目的全局“最后选中标签”。右键动作先捕获该编辑器的选区快照并解析目标 session，再追加到该 session 待发送区；用户提交问题后发送，这一提交边界现已确认。

每次请求携带 sessionId、turnId、requestId 和 projectInstanceId；第一版已确认流式显示，正文增量、完成结果与错误都归原 session/轮次/attempt。切换或关闭标签只改变显示，任务继续；不得因当前焦点改变而把返回内容添加到另一个 session。

用户已确认同一 session 同时只执行一个生成/整理任务，新内容留草稿，当前任务完成后由用户再发送；不同 session 可独立提问，具体全局配额仍待定。关闭标签不取消任务；显式取消、关闭项目与删除 session 具有独立语义。底层请求停止不及时，也应阻止已取消、已删除或旧项目实例的回包继续改写有效状态。

每次检索绑定实际使用的课程索引代次与片段来源。共享课程库更新不改写正在回答的引用映射，旧回答保留其原版本证据。课程库共享与请求私有证据、聊天记忆及代码快照的隔离同时成立。

### 13.4 保存与恢复（提案中的技术规则）

保存聊天记录及附加代码快照是已确认需求，现已补充恢复全部草稿与标签布局。持久化至少要能还原 session 身份、所属项目、消息顺序、已附加快照、回答引用、待发送内容与标签状态；存储格式和保存时点待定，MVP 不引入自动数据修复。详见 `PERSISTENCE.md`。

代码快照建议记录文本、文件定位信息、语言、选区范围、捕获时间与文件版本标记。恢复显示保存时的快照；源文件已经变化时，应能识别快照与当前文件的差别，避免把历史内容悄悄替换成新选区。

恢复聊天视图与重新发出网络请求分开处理。建议重启读取最后完整保存的数据，未完成请求不视为成功；不自动重发。开发暴露读取错误；实际使用提示恢复不完整并限制受影响功能，不清空档案或伪装恢复成功。具体交互见 `ERROR_HANDLING.md` 提案。

对话窗口是 session 的视图；用户已确认关闭标签不删除会话也不取消任务，可从会话列表重开。标签处另有删除 session 的动作，删除后清除该 session 全部记录，详见 `PERSISTENCE.md` 第 6 节。模型输入压缩不删除原始档案，用户主动删除 session 则清除其完整档案与派生数据。

### 13.5 后续验证场景（尚未执行）

1. 同项目创建 A、B 两个 session，分别附加不同选区，提交时只使用目标 session 的历史和快照。
2. A 请求发出后切到 B，A 的返回结果仍只归入 A；错误、取消和流式片段同样路由。
3. 关闭项目再打开，旧 projectInstanceId 的返回结果被拒绝，保存的 session 与代码快照能恢复。
4. 共享课程库更新期间，正在回答的 session 保持本轮证据版本，其他 session 可在下一轮使用新代次。
5. 重启后恢复多个 session 的消息顺序和快照；源代码变化不悄悄改写已保存的上下文。
6. 项目 A、B 各有当前标签时，从 A 的编辑器右键提问只进入 A 的当前 session；A 没有可用当前会话时，新建并绑定 A。

### 13.6 Tool Window 标签页交互

| 交互 | 行为 | 状态 |
| --- | --- | --- |
| session 呈现 | 每个 session 对应 Tool Window 内的一个对话标签，以标签页切换 | 用户已确认 |

| 标签绑定 | 使用稳定 sessionId，标题和位置只用于显示；按项目维护 activeSessionId | 实现提案 |
| 标签内容 | 呈现该 session 的聊天历史、代码快照/附件、输入草稿与请求状态 | 界面提案 |

已在 A 标签发出的请求始终回写 A 对应的轮次。切换到 B、调整标签位置或改变标题都不改变请求身份。关闭标签、取消请求和删除 session 的不同语义应落实到事件契约，不能依赖标签位置或当前显示内容推断。

## 14. 类型化消息片段与 LLM 文本投影

### 14.1 已确认的边界

选中代码使用区别于普通对话文本的渲染 schema；向 LLM 发起调用时仍提供文本。再次选区采用追加新片段的语义。持久化及界面保留类型与代码快照，不要求生成模型接口支持新的代码模态。

### 14.2 概念 schema（字段为提案）

| 对象 | 建议字段 | 意义 |
| --- | --- | --- |
| Message | messageSchemaVersion、messageId、sessionId、role、createdAt、parts | role 表示发言方，parts 保留有序内容；代码不新增一种发言角色 |
| TextPart | partId、type=text、text；拟加 format=markdown | 保存对话 Markdown 原文，渲染 HTML 为派生显示 |
| CodeSelectionPart | partId、type=code-selection、snapshotId、language、sourceLabel、range | 独立代码片段的渲染与来源信息，代码正文引用固定快照 |
| CodeContextPart | partId、type=code-context、contextKind、snapshotId、captureId、来源/版本 | method / class-structure 自动补充片段，使用固定正文；类结构明确为摘录，详细范围见第 19 节 |
| CodeSnapshot | snapshotId、codeText、来源文件/版本、选区范围、捕获时间 | 选取时的不可变正文；文件路径承担定位，不承担正文存储 |
| LlmInputProjection | requestId、sessionId、所选 messageId/partId、历史边界、文本化结果 | 本轮模型输入的派生结果，不覆盖持久化原始消息 |

概念关系为 SessionDraft → 用户提交 → Session 中有序 Message → 有序 TextPart / CodeSelectionPart。用户已确认选区先进入待发送区；普通文字与多个代码片段一起提交。具体草稿版本、消息身份与持久化事务字段仍为提案。

UI renderer 按片段类型呈现段落或带来源的代码片段。LLM projector 按本轮角色和顺序把内容转换成文本；代码正文、必要的语言/来源说明仍属于文本数据。schema、快照身份及本地显示状态由应用管理，不直接作为模型专用附件协议。

### 14.3 追加、去重与历史恢复（实现提案）

一次选区动作生成一个有独立 partId 的新片段；后续选区继续追加，不覆盖旧快照。再次选取相同文本与系统重复注入同一 partId 是不同情况，应保留动作身份，避免按文本内容去重而吞掉用户的追加。

请求开始时固定本 session 的消息/片段集合和历史边界。若历史已经由这些结构化片段投影，不再从另一个“代码上下文集合”重复加入相同片段；同一 partId 在同一次请求中最多投影一次。之后追加的代码属于后续请求，不改写已经发出的请求快照。

追加保存不等于每轮无限重发所有历史。持久化保留用户要求的聊天和代码快照，本轮提示词按执行成员实施确认的预算与选择规则组装；未进入本轮提示词不意味着删除历史。

## 17. 请求生命周期的共通规则（提案）

本节沿用现有 session、RequestEnvelope、ChatTurn 和 CompactionJob，不新增通用状态机框架。用户已确认检索故障自动转为标记的通识回答、关闭标签任务继续、每 session 同时一个任务；以下身份、阶段与提交算法仍是实现提案。

### 17.1 活跃操作、阶段与结果分开

| 内容 | 建议表达 | 意义 |
| --- | --- | --- |
| 活跃操作 | session 内的操作类型和原有 requestId / jobId | 回包、取消和最终提交针对确切操作，不由当前标签推断 |
| 执行阶段 | 提交保存、检索、整理上下文、生成、保存回答 | 用于显示进度；自动整理属于同一次回答请求，手动整理独立且不触发回答 |
| 操作结果 | 成功、失败、已取消、中断 | 终止结果只提交一次；“检索已降级但回答完成”是带降级标记的成功，不是假装检索成功 |
| 视图状态 | 标签打开/关闭、当前选中项 | 与操作结果分开；标签位置和当前焦点都不承担请求身份 |

用户提交后固定本轮 message/part 边界；之后编辑草稿或追加代码只改变待发送内容。回包提交时再次检查 session 仍有效、本次项目打开实例仍相同、操作身份仍匹配且未终止；旧操作的完成通知不能清掉新操作的忙碌状态。

单任务约束覆盖一次回答的提交、检索、自动整理、生成及最终保存全过程；自动整理不能被当成另一个可并发手动任务。手动整理独立占用该 session 的活跃操作，忙时不能再启动发送或手动整理。草稿编辑和选区追加继续可用，接口入口也检查忙碌状态，不能只依赖按钮置灰；拒绝忙时发送不消费草稿，不建立队列，也不在任务完成时自动发送。

### 17.2 取消与完成的竞争

停止动作携带 sessionId 及明确的操作标识，先使本地操作失效，再请求底层取消。底层未及时停止不能赋予迟到片段新的写入权。最终成功提交与取消的状态更新只允许其中一个先取得终止结果；已完成操作不能被迟到停止动作改写为取消，已取消操作不能被迟到完成改写为成功。删除会话是生命周期控制动作，忙时仍可执行，先撤销写入权再清理记录，不受“不能启动第二个生成/整理任务”的限制。

第一版采用流式显示。取消或生成故障前已有的部分回答保留未完成状态，不能伪装完整答案；已保存用户问题、代码及本次之后新增的草稿都不因停止而删除。显式取消不是检索故障，不进入通识降级继续生成；断流不自动重发整请求，用户重试使用新 attempt，不拼旧前缀。

关闭项目与关闭标签分别处理。项目生命周期结束应使该 projectInstanceId 的操作失效；建议取消底层任务，并由生命周期协调方委托应用级存储按原实例/操作身份完成本地终止及释放忙碌槽，不依赖旧模型回调。每次重开先处理旧实例遗留操作，再允许新发送；不接收旧实例回包，不改写新操作。具体 API 和取消界面仍为提案，详见 `ENGINEERING_BLUEPRINT.md` 第 6 节。

关闭标签后，操作继续归属于 session 服务，不依赖已释放的视图组件。会话列表可重新打开并渲染其最新保存状态；后台任务完成不自动重新打开标签。若发生异常，实际使用提示由项目级公共入口承接并保留到原 session，不能因标签关闭而丢失；具体通知样式为提案。关闭标签更新打开标签布局；全部标签关闭后，不把隐藏 session 视为当前标签，右键仍按已有规则新建会话。

通过标签删除 session 时，草稿延迟保存、错误/流式回调、摘要候选、界面布局保存也须一并失效，不能只阻止最终回答。所有写入检查 session 存在且操作有效，不能自动新增已删除身份。删除完成后该 session 不再列出或恢复；共享课程资料保留，删除事件本身不新建替代会话。

### 17.3 检索故障后的自动降级

实际使用中，查询嵌入/检索故障先提示，再在原 requestId/turnId 内自动进入通识回答路径，不另提交一条用户问题。保存可区分的检索结果状态及回答模式；该路径不带本轮 RAG 证据集合，明确显示“课程检索失败，当前回答未使用课程证据”。本会话已提交的问题和代码仍按原冻结快照处理，输入预算与压缩规则继续适用。

历史助手文本或摘要只作会话背景，不能把其中旧引用提升为本轮有效证据。提示故障、回答上的降级标记和记录中检索状态一致；不能只弹一个瞬时提示后把答案展示为正常课程回答。若生成服务也失败，停止生成并提示，不循环进入另一条通识请求或擅自更换模型。开发/调试链路仍暴露检索错误，不默认执行此产品降级分支；该分支用明确故障场景单独验证。用户另已确认正常无命中和未建课程索引均自动通识回答；这两者是业务分支，分别标明“无相关资料/未建课程库”，不作为异常兜底。

### 29.6 JUnit 生成工具内部流程（代理提案）

1. 接受 requestRef/cardId 与明确修订；宿主解析固定源码、原始用户需求、归属及运行资格。
2. 从绑定的用户需求重算有效场景长度；纯空白按 0 处理，但原文保留。0 返回 SCENARIO_REQUIRED，内部生成模型订阅数必须为 0。正长度不代表语义充分，仍可返回澄清需求。
3. 模型不能自己提供场景以绕过用户输入要求，也不能通过自报长度获得资格。真实 MCP 接入时由宿主适配器注入受控字段，服务端核验；长度是业务字段，不是 MCP 内建权限机制。
4. 从固定目标及有界环境准备 JUnit 上下文。识别目标模块的 Java/JUnit 配置；不把插件自己的测试依赖当用户项目依赖，不自动修改构建。
5. 同一 attempt/card/sourceRevision/requirementRevision 的重复生成共用幂等记录。显式新 attempt 可重新生成；断流不自动重发。
6. 工具内部只执行一次 tools=[] 的受控模型请求，沿用所选模型配置，无递归 ReAct、无第二 session 槽、无内部自动重试。所有输入/输出/次数/usage/耗时计入父预算。
7. 子生成按父 toolCallId 归属发布流式预览；正常结束、结构校验及耐久提交共同成立才成为候选。只做过静态检查的，不宣称已编译或测试通过。
8. 完整测试源码存为独立产物；工具观察返回有界概要及产物引用，避免外层再次生成一份不同代码。JUnit 生成错误不走课程检索通识降级。
