# F0 插件 IJ 黑盒验收方案

日期：2026-10-24。执行人：用户。目标：本机 IntelliJ IDEA 2026.2.3 / IU-262.10968.63，Windows。本文中的人工项目初始均为 **NOT_RUN**；自动白盒通过不代替本表结果。仅验收 F0，不包含生成 JUnit、自动改代码或执行任意工具。

## 1. 安装前准备

- [ ] 在 IJ 的 Help → About 核对真实版本/build。安装文件夹名可能仍含 2026.1.1，以 About 为准。若不是上述 build，先记录差异，不把测试结果算作该版本通过。
- [ ] 准备两个独立的测试项目目录 A、B，并在同一个 IJ 进程的不同窗口打开。不要用重要项目做删除/移动测试，也不要用两个 IJ 进程同时占用同一插件数据目录。
- [ ] 保留需要的现有聊天资料；本方案只删除特意创建的测试会话。插件记录位于 IJ 配置目录下 `courseassist-f0`，不会因卸载插件自动作为测试步骤清空；不要直接删除数据库来制造“首次启动”。
- [ ] 备好生成、嵌入两类服务的配置及凭据。可以是不同平台/不同 key，不能假设一把 key 通用。真实提问、嵌入 PDF、整理历史会产生服务请求，按自己的账号额度控制测试规模。
- [ ] 确认服务支持当前实现路线：生成为 DeepSeek 风格的 `/chat/completions` SSE（包括实际使用的工具协议），嵌入为 OpenAI 兼容接口。提供方名称字段只是配置标识，不会自动切换到任意供应商协议。

### 安装插件

1. 使用本次交付的 `build/distributions/IJ-Plugin-Java-0.1.0-dev.zip`，不解压。确认文件修改时间/哈希对应第五组验证记录，不使用旧包或 `f0-runtime-smoke.jar`。
2. IJ 打开 Settings → Plugins → 齿轮 → Install Plugin from Disk…，选择上述 ZIP。已有同 ID 版本时按 IJ 提示更新。
3. 应用变更并重启 IJ。Plugins → Installed 中确认 **Course Assistant F0** 已启用，Java 插件也已启用。
4. 打开测试项目 A，从右侧 **Course Assistant** 或 View → Tool Windows → Course Assistant 进入。
5. 等待恢复完成。若显示项目身份待确认：全新/复制测试项目选“作为新项目打开”；只有迁移用例才选“关联已有项目会话”。若应用存储初始化失败，记录错误并排障后重启，不清空原数据。
6. 界面应出现“草稿与代码 / 聊天回答 / 全部会话 / 资料与配置”，不是旧的“F0 开发基线”占位文本。

### 填写 API key 与服务配置

1. 进入“资料与配置”，确认工作状态为 **OFF**。若为 ON，先点“停用”，等待 OFF。
2. 点“服务配置”，按实际平台控制台/接口说明填写两栏。下表的示例标识可以自定，地址、模型、维度必须使用真实资料，不照抄不存在的示例模型。

| 字段 | 生成服务 | 嵌入服务 |
| --- | --- | --- |
| 配置 ID | 如 `generation-main`，非空 | 如 `embedding-main`，非空 |
| 提供方 | 实际服务名称，非空 | 实际服务名称，非空 |
| 地址 | API base URL；实现会追加 `/chat/completions`，不要填写完整聊天接口路径 | OpenAI 兼容 API base URL；按平台是否要求 `/v1` 填写，勿重复追加完整 `/embeddings` 路径 |
| 模型 ID | 账号真实可用且支持所需 SSE/工具协议的准确 ID | 账号真实可用的准确嵌入模型 ID |
| 嵌入维度 | 可留空 | 必填正整数，必须与服务实际返回维度一致；不能只按模型别名猜测 |
| 新 API key | 在密码框填写生成凭据 | 在密码框填写嵌入凭据 |
| 移除现有凭据 | 正常配置不要勾选 | 正常配置不要勾选 |

3. 点确定，确认操作被接受。重新打开配置时 key 不应回显；空白密码框表示“不更改现有凭据”，不表示凭据丢失。
4. 点击“启用”，等待 **ON**。启用只验证本地配置并构造客户端，**ON 不证明远端 key 有效**，后续提问/PDF 导入才验证实际调用。
5. 凭据交由 IJ 平台凭据服务保存。若 IJ 提示选择/解锁凭据存储，按平台提示完成。测试报告、截图、聊天和仓库中都不要填写真实 key。

### PDF 和 Java 测试材料

使用同目录 [blackbox-fixtures](blackbox-fixtures/) 中的可分发合成文件：

| 文件 | 固定内容与用途 |
| --- | --- |
| `course-a-v1.pdf` | 3 个物理页；第 2 页空白；第 3 页 `F0-ALPHA` 的重试间隔为 **17 minutes** |
| `course-a-v2.pdf` | 3 个物理页；第 2 页空白；第 3 页 `F0-BETA` 为 **23 minutes**，用于替换 A |
| `course-b.pdf` | 3 个物理页；第 2 页空白；第 3 页 `F0-GAMMA` 为 **31 minutes**，用于检验目标绑定 |
| `broken.pdf` | 故意损坏的非 PDF 文本，用于导入/替换失败 |
| `CaptureSample.java` | 含字段、twice 方法及无关方法；复制到测试项目 A/B 的 Java 源目录 |

先用 PDF 阅读器逐一确认物理页 1、空白页 2、正文页 3。页码是从文件第一页起的物理序号，不是课件印刷页号。

导入步骤：保持 ON →“资料与配置”→“导入 PDF”→选择 `course-a-v1.pdf` →等待资料行就绪及课程库 READY。按钮提示“操作已接收”只说明接收命令，必须等待最终状态；记录失败提示，不把失败行当作可检索资料。随后再导入 B，不并发导入以免库版本竞争影响首次准备。

## 3. 黑盒证明边界与失败回报

界面测试能验证显示、交互、重启后的可见状态；不能单凭回答看起来正常，证明中断正文未进入后续模型/摘要、H2 私有行全清、CAS 并发发布或一次订阅。上述内部不变量见 [WHITEBOX_TESTS.md](WHITEBOX_TESTS.md) 的自动断言和证据，不能用肉眼猜测代替。

服务工具调用/无命中/摘要是否触发受真实模型影响；没有触发就写 NOT_RUN。PDF 跳页还受系统阅读器影响。这里没有预先宣称真实 API、人工可视体验或真实课件规模通过。

每个 FAIL/BLOCKED 按下面模板反馈，不放 key，也不要整份上传含私有课程内容的日志：

```text
用例 ID：
测试日期 / IJ build / 插件 ZIP 哈希：
项目/会话（可匿名）：
操作步骤：
预期：
实际：
截图或已脱敏错误类型：
生成/嵌入配置 ID、非秘密模型 ID（必要时）：
重启后是否仍复现：
```

验收汇总：PASS __ / FAIL __ / BLOCKED __ / NOT_RUN __。先完成核心 P0–P4；任何失败不得用勾选“通过”替代解释。用户完成后的记录再决定人工验收状态。
